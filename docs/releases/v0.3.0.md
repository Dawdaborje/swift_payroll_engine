# Swift Payroll Engine 0.3.0

The first release published on crates.io, as three crates:

| Crate | What it is |
|---|---|
| [`swift_payroll_expr`](https://crates.io/crates/swift_payroll_expr) | An exact-decimal expression language with CEL-style syntax. |
| [`swift_payroll_core`](https://crates.io/crates/swift_payroll_core) | The payroll kernel: structures, compiling, calculating, rule packs. |
| [`swift_payroll_engine`](https://crates.io/crates/swift_payroll_engine) | The command line (`cargo install swift_payroll_engine`). |

## Highlights

* **Deductions taken in a stated order.** With `"negative_net": "zero"`, deductions are taken from pay by
  `priority` (refunds first) until pay runs out. Each line reports what it could not take as `shortfall`, and
  `gross - deductions = net` still holds.
* **Exact precision mode.** `"precision": "exact"` makes any result that cannot be held exactly, such as
  `1 / 3`, an error instead of rounding it. In every mode, a non-zero product that would round to zero is now an
  error, never a silent zero.
* **Typed inputs.** `"type": "number" | "text" | "bool"` on an input is checked before anything is calculated.
  Amounts may be written as decimal text (`"1500.50"`), which is always read exactly.
* **Safer rule packs.** `PackChecks` refuses, by default, a pack nobody has checked against the law, a pack in
  another currency, or one not in force on the pay date. Pack descriptions are validated more strictly.
* **Structured errors.** `EngineError`, `RuleError` and the expression `Error` carry kinds and the person,
  component or input at fault, so a host can react without parsing messages.
* **Warnings.** `Compiled::warnings()` (and the command line, on standard error) report inputs and constants
  nothing reads.
* **Golden payslips** recorded by hand guard every digit against changes in this code or its dependencies.

## Upgrading from 0.2

1. Rename the dependencies: `sp_expr` → `swift_payroll_expr`, `sp_engine` → `swift_payroll_core`.
2. Replace `run(&input, explain)` with `run(&input)` or `run_explained(&input)`, and the `bool` passed to
   `run_all` / `for_each` with `Detail::Lines` or `Detail::Explained`.
3. Update code that matches on `EngineError` or rule-pack errors (`String` before, structured now).
4. Pass `&PackChecks` to `RulePack::as_component`. Use `PackChecks::for_structure(&structure).on(pay_date)` for
   real pay; `.allow_unverified()` only for tests and demonstrations.
5. If you relied on `exact-json` being on by default in `swift_payroll_core`, enable it explicitly, or send large
   amounts as decimal text.
6. Remove any unknown fields from structures, inputs and rule packs: they are now errors.

The full list is in [CHANGELOG.md](https://github.com/Dawdaborje/swift_payroll_engine/blob/main/CHANGELOG.md#030---unreleased).

## Verification

* `cargo test --workspace` passes on Linux, macOS and Windows, on stable and on Rust 1.85.
* All 36 rule packs in `swift_tax_rules` load and pass their own tests with the stricter parsing.
* Stress run: 100,000 employees × 10,000 rules, 0 invariant violations, 0 mismatches against an independent
  oracle, every deliberately broken employee refused alone.
* Kani: the proof harnesses listed in [kani/README.md](https://github.com/Dawdaborje/swift_payroll_engine/blob/main/kani/README.md)
  pass. They are boundary and example proofs, not a proof of the whole engine.

## Not in this release

Year-to-date and cumulative tax, pay calendars, retroactive recalculation, several currencies per structure,
and language bindings (Python and JavaScript are planned). The engine is not legal or tax advice, and most rule
packs in `swift_tax_rules` are marked unverified.
